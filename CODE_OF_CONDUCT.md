# Code of Conduct

## Our Pledge

We as contributors and maintainers of **Avatox** — a fast and lightweight React library for generating personalized avatars — pledge to make participation in our project and community a harassment-free experience for everyone, regardless of age, body size, visible or invisible disability, ethnicity, sex characteristics, gender identity and expression, level of experience, education, socio-economic status, nationality, personal appearance, race, caste, color, religion, or sexual identity and orientation.

We pledge to act and interact in ways that contribute to an open, welcoming, and healthy open source community.

---

## Our Standards

### ✅ Behavior that contributes to a positive environment

- Writing clear, constructive issue reports and pull request descriptions
- Providing helpful and respectful code review feedback
- Being welcoming to contributors of all experience levels — from first-timers to seniors
- Gracefully accepting feedback on your contributions
- Focusing discussions on the technical merits of the library (performance, API design, TypeScript types, accessibility, etc.)
- Crediting others' ideas and work appropriately

### ❌ Unacceptable behavior

- Dismissing or belittling contributions because of a contributor's experience level
- Insulting or derogatory comments in issues, pull requests, or discussions
- Personal attacks unrelated to the technical discussion
- Spamming issues or PRs with off-topic or low-effort content
- Publishing others' private information without explicit permission
- Harassment of any kind, public or private

---

## Scope

This Code of Conduct applies to all Avatox community spaces, including:

- GitHub Issues and Pull Requests
- Code review comments
- GitHub Discussions
- Any public space where you are representing Avatox (e.g., social media, community forums, or developer events)

---

## Contribution Standards

Since Avatox is a UI component library, contributions should also follow these technical expectations:

- **React compatibility** — contributions must support React 16 and above
- **TypeScript** — all new features must include proper type definitions
- **Accessibility** — components must maintain ARIA support for screen readers
- **Testing** — new features and bug fixes should include tests (via Vitest)
- **Tailwind CSS** — styling contributions should follow the existing Tailwind-based approach
- **Linting** — run `npm run lint` and `npm run typecheck` before submitting

These are not grounds for dismissal — they are shared goals we work toward together.

## Enforcement

Project maintainers are responsible for clarifying and enforcing these standards. They may remove, edit, or reject comments, commits, code, issues, or other contributions that violate this Code of Conduct, and will communicate reasons when appropriate.

Consequences for violations may include:

1. **Correction** — A private written warning explaining the violation.
2. **Warning** — A formal warning with a period of restricted interaction.
3. **Temporary Ban** — Temporary removal from community spaces.
4. **Permanent Ban** — Permanent removal for repeated or severe violations.
